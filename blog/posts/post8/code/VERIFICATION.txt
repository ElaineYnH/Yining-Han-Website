1. Question and motivation
   blog8.qmd opening asks what a simulated 53% poll tells us about a population
   even split. The sample size and uncertainty have a concrete interpretation.
2. Clear explanation
   Three linked sections explain resampling, new polls versus resamples,
   long-run coverage, and testing a specified null in undergraduate language.
3. Interpretation and takeaway
   Numeric CI, coverage, widths, null rejection rate and p-value are interpreted.
   Failure to reject is explicitly distinguished from establishing a true null.
4. Data and presentation
   Simulation status is explicit. SOURCES.txt and the README document every
   parameter. Three substantive figures carry the argument; mobile plots exist.
5. Repository organization
   code/, data/, results/, requirements.txt, and README.md contain complete
   replication materials. The article links directly to those materials.
6. Reproducibility and coding practices
   Fixed separated random streams, generated CSV/JSON outputs and templates
   insert numerical results programmatically. The existing article date is
   preserved during regeneration.
7. Bootstrap distribution
   bootstrap_means() literally resamples the observed responses with replacement
   20,000 times. Figure 1 shows the resulting distribution and percentile CI.
8. Approximately 95% coverage
   coverage_experiment() draws 5,000 NEW polls for every n, creates a fresh
   2,000-resample distribution for EACH poll, and checks known truth 0.55.
   Figure 2 displays unselected intervals and the all-poll coverage count.
9. Test statistic under the null
   null_experiment() simulates 50,000 new polls with p=0.50, independently of the
   original p=0.55 model. The statistic is the support share.
10. Rejection regions and p-values with visualization
    Figure 3 shows the same null histogram twice: predefined two-sided 5%
    rejection regions above, observed-result tail areas below. Boundary ties,
    discreteness, Monte Carlo correction, and the interpretation are correct.

Extra prompt recommendation: Figure 2 permits changing n and confidence level;
precomputed experiments update both the displayed intervals and the summary.

SPACING FIX AFTER PUBLICATION (2026-10-31, America/New_York)
The original automatic height calculation used documentElement.scrollHeight,
which includes the iframe viewport. Sending that height back with extra padding
created a feedback loop and left excessive blank space on the WEB page.
The earlier browser check established enough height, but missed excess height.

The explorer now measures its main content box. The article sets the frame to
that measured height only when it changes, and requests an initial measurement
after the iframe loads. Both generation templates contain the correction.
Browser printing uses a static default coverage plot; the interactive frame is
hidden for print, without retaining its occupied space.

Corrected Chromium checks passed all nine settings and viewport widths 390, 768,
1280 and 1920px. Frame-to-content extra height was below 1px. Desktop frame
height was 725px for 724.90625px of content; the caption followed after its normal
17px margin. Waiting while idle did not increase the frame height. The print
media fallback, keyboard controls, relative links, offline explorer and listing
checks passed. No horizontal overflow or JavaScript errors were found.
All CSV, JSON and PNG files are byte-identical to the original delivery; the
article date, analysis and numerical conclusions were preserved.
